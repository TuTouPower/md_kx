# Task spec

## 背景

mdformat 核心是 CommonMark 解析器，默认不解析表格。表格支持依赖 GFM 扩展（如 mdformat-gfm 插件），且启用后强制 pad 对齐，不符合仓库"表格紧凑"要求。用户提出二次开发需求：内置表格解析能力，提供三态开关让用户选择表格处理方式。

## 契约区

### 范围

- mdformat 核心内置表格解析能力（不依赖 GFM 扩展）
- 新增三态表格处理开关：不处理表格 / pad 对齐 / 紧凑
- 各态下表格语法正确、可正常渲染

### 非范围

- 不改变无表格文档的行为
- 不涉及表格内跨行/复杂单元格合并等 GFM 扩展语义（按现有表格语法子集）

### 风险与回退

- 风险：内置表格解析与现有插件机制（如已装 mdformat-gfm 提供表格）冲突或重复；解析边界误吞普通文本竖线。
- 回退：AC-005 保证无表格文档不受影响；表格识别失败回退重新设计判定；与插件并存策略由 Step 1 spike 确认。

### 依赖与约束

- 无前置依赖；优先复用 markdown-it-py 既有能力，不引入新第三方依赖；不破坏现有 CommonMark 合规性（无表格文档）。
