# p008 表格三种输出风格

- 来源：用户提出
- 内容：表格格式化必须能明确选出三种输出风格，且三种风格的单元格空白规则互不相同。旧需求里「紧凑 = 不按列对齐」不够：调用方需要零空格的 `|a|b|`，也需要两侧各一空格的 `| a | b |`，也需要按列补齐的 pad。本条只定义可观察输出，替代对 compact / 单空格 / pad 的歧义。
- 处理：t008

## 目标

格式化一张 Markdown 表时，用户选择一种风格，整表按该风格写出。同一次格式化里所有表用同一风格。风格只影响表格行的空白与列宽，不改变单元格里的有效文本、不改变表格行列结构、不改变表以外的文档。

必须支持且仅支持下面三种风格。

## 三种风格

输入同一张表（单元格有效文本为 `a`、`b`）：

### compact

单元格两侧不加空格。分隔行用最短合法标记，两侧不加空格。

```markdown
|a|b|
|---|---|
```

### spaced

单元格两侧各恰好一个空格。分隔行两侧各恰好一个空格。不按列宽补空格。

```markdown
| a | b |
| --- | --- |
```

### pad

先按 spaced 的方式在单元格两侧各留一个空格，再按列把单元格补到该列最宽，使竖线对齐。

```markdown
|    a   | b |
| ------ | - |
```

（上例仅示意「按列补齐」；实际补多少空格由该列最宽单元格决定。短单元格右侧补空格，分隔行长度跟列宽走。）

用户举例中的 `|    a   |   b   |` 属于 pad：空白用于列对齐，不是第三种之外的第四种规则。

## 共同规则

1. **有效文本**：去掉单元格两端仅用于填充的空白之后，剩下的内容是有效文本。有效文本内部空白原样保留。`|  hello world  |` 的有效文本是 `hello world`。
2. **三种风格都写合法表**：输出仍是可渲染的 Markdown 表格，列数、行数、表头与表体关系与输入一致。
3. **对齐语义保留**：输入分隔行里的左/中/右对齐冒号，输出仍表示同一对齐。compact 写在竖线内侧且不加额外空格（如 `:---|`、`|:---:|`、`|---:`）；spaced 在冒号外侧各留一个空格；pad 在保留冒号的前提下按列宽拉长分隔段。
4. **转义竖线保留**：单元格内的 `\|` 仍是单元格内容，不拆列。
5. **空单元格**：compact 写成相邻竖线（`||`）；spaced 写成 `| |`；pad 按该列宽度补空格。
6. **幂等**：同一风格下再格式化一次，文件不发生变化。
7. **非表内容不受 table 风格影响**：标题、列表、代码块、普通段落、front matter 不因切换这三种风格而改变。
8. **非法风格名**：配置或命令行写了三种之外的名字时，格式化失败并报错，不改文件。

## 配置

- 配置项与命令行都能选择风格，名字为 `compact`、`spaced`、`pad`。
- 仓库配置与命令行都能指定；命令行优先于仓库配置。
- 未指定时的默认风格：`spaced`（两侧各一空格，且不按列对齐）。

## 与旧含义的关系

旧文档把 compact 说成「不按列对齐」，实际输出与 spaced 相同。本需求重新定义：

| 风格 | 单元格空白 | 是否按列对齐 |
| --- | --- | --- |
| compact | 两侧零空格 | 否 |
| spaced | 两侧各一空格 | 否 |
| pad | 两侧至少一空格，再按列补齐 | 是 |

不再把「原样不改表」算作这三种风格之一。选了其中一种，表就必须按该风格写出。

## 验收

- 同一输入表，分别指定 compact / spaced / pad，输出分别符合上文三种示例的空白规则。
- compact 的输出中，单元格有效文本与两侧 `|` 之间没有空格。
- spaced 的输出中，单元格有效文本与两侧 `|` 之间各恰好一个空格；同一列宽度可以不同。
- pad 的输出中，同一列各行（含分隔行）外层 `|` 对齐；有效文本两侧至少各有一个空格。
- 含对齐冒号、转义竖线、空单元格的表，三种风格下语义不变，且二次格式化无 diff。
- 不含表的文档，三种风格下输出一致。
